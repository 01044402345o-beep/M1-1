### 선정 이유

1. **수집 난이도가 낮다** — API 키 불필요, 코드 한 줄로 수집 가능. 절약한 시간을 해석 품질에 투입한다.
2. **요일 분석이 의미를 가진다** — 24시간 365일 거래되므로 주말 데이터가 존재한다. 주식 데이터로는 불가능한 질문(주말 효과)을 던질 수 있다.
3. **변동성이 크다** — 이동평균, 변화율, 롤링 표준편차 등 기법 적용 결과가 시각적으로 뚜렷하게 드러난다.
4. **추세 전환 구간이 명확하다** — "관찰 vs 해석" 분리 서술의 소재가 풍부하다.

### 기간 선정 근거

2023년 이후 3년 9개월 구간은 상승·하락·횡보 국면이 모두 포함되어 추세 전환 구간이 여러 번 나타난다. 또한 연도가 3개 이상 확보되므로 월별 집계를 연도별로 교차 비교할 수 있다 (2년치만으로는 샘플이 부족해 "월 효과" 주장이 성립하기 어렵다).

## 4. 데이터 정제 기준

### 4.1 결측치

1. `asfreq('D')`로 전체 날짜에 재색인하여 누락된 날짜를 명시적으로 드러낸다.
   > [구현 노트, 2026-10-01 최종 리뷰 반영: 실제 구현(`btc_analysis.reindex_daily`)은 `asfreq('D')`가 아니라 `df.reindex(pd.date_range(...))`를 쓴다. 결과는 동일하지만 호출한 API 이름이 다르므로 REPORT.md와 코드는 `reindex(pd.date_range(...))`로 기술한다. 이 문서는 과거 설계 기록으로 보존하고, 아래에 주석만 추가한다.]
2. 결측 건수와 해당 날짜를 리포트에 실제 수치로 기재한다.
3. 가격 컬럼은 `ffill`(직전 종가 유지)로 채운다. 근거: 거래가 기록되지 않은 날은 "값이 없는" 것이 아니라 "직전 가격이 유지된" 상태로 보는 것이 금융 시계열의 관례다.
4. **`ffill`로 채운 날짜의 수익률은 계산에서 제외한다.** 근거: 가짜 0% 수익률이 섞이면 변동성이 과소추정된다.

### 4.2 이상치

**원칙: 탐지하되 제거하지 않는다.**

- ±3σ 및 IQR 기준으로 극단적 수익률 일자를 **탐지하고 목록화**한다.
- 그러나 제거하지 않는다. 근거: 암호화폐의 하루 ±10% 변동은 측정 오류(노이즈)가 아니라 분석 대상 신호 그 자체다. 이를 제거하면 "변동성 분석"이라는 목적 자체가 훼손된다.
- 예외적으로 다음은 데이터 오류로 간주하여 제거 대상에 둔다.
  - 가격이 0 또는 음수
  - 전일 대비 절대 변동률 50% 초과
  - High < Low 등 논리적으로 모순된 행

이 판단 과정과 근거를 리포트에 서술한다. 미션의 "결측치/이상치가 무엇이며 어떤 기준으로 처리했는지 설명할 수 있다"는 학습 목표에 직접 대응하는 항목이다.

## 5. 적용 분석 기법

| 기법 | 적용 이유 |
| --- | --- |
| 이동평균 7 / 30 / 90일 | 단기 노이즈를 제거해 추세를 분리하고, 교차 시점으로 추세 전환 구간을 식별한다 |
| 일별 변화율 · 누적 수익률 | 가격 레벨이 크게 다른 구간을 공정하게 비교하기 위해 절대 가격 대신 비율로 환산한다 |
| 30일 롤링 표준편차 (연율화) | 변동성이 시간에 따라 어떻게 변하는지 측정한다 (Q2) |
| 월별 / 요일별 집계 | 반복되는 패턴(계절성)의 존재 여부를 검증한다 (Q3, Q4) |
| 최대 낙폭 (MDD) | 하락 리스크의 규모를 단일 수치로 요약한다 |

집계 단위는 **일(日)** 을 기본으로 한다. 근거: 비트코인의 주요 가격 변동은 하루 단위로 발생하며, 주/월 단위로 집계하면 분석 대상인 급변동이 평균에 흡수되어 사라진다. 다만 패턴 탐색(Q3, Q4)에서는 노이즈를 줄이기 위해 월별·요일별로 재집계한다.

## 7. 베이스라인 예측 설계 (보너스 B)

### 구성

- **분할**: 마지막 30일을 홀드아웃으로 분리, 그 이전 데이터만 학습에 사용 (미래 데이터 누수 차단)
- **모델 3종**
  1. Naive — 마지막 관측값을 그대로 유지
  2. 이동평균 — 최근 7일 평균값을 유지
  3. Drift — 최근 추세의 평균 변화량을 선형 연장
     > [구현 노트, 2026-10-01 최종 리뷰 반영: 실제 구현(`btc_analysis.forecast_drift`)은 "최근 추세"가 아니라 **학습 구간 전체**의 평균 일간 변화량 `(마지막값 − 첫값) / (길이 − 1)`을 선형 연장한다. 위 스펙 문구는 이 구현 전의 설계 의도이며, REPORT.md와 코드는 전체 구간 평균을 기준으로 기술한다. 이 문서는 과거 설계 기록으로 보존하고, 아래에 주석만 추가한다.]
- **평가 지표**: MAE, MAPE, 방향 정확도(상승/하락 방향을 맞춘 비율)

### 예상 결론과 서술 방향

가격 시계열은 랜덤워크에 가까워 Naive 모델을 이기기 어렵다. 미션이 "정확도보다 가정·한계 설명에 집중"을 명시했으므로, **"단순 모델을 이기지 못했다, 그리고 그 이유는 무엇인가"** 가 오히려 요구에 부합하는 서술이다. 수치를 좋게 보이도록 조작하지 않는다.

명시할 가정과 한계:

- 과거 패턴이 미래에 반복된다는 가정에 의존한다
- 외부 변수(규제, 거시경제, 뉴스)를 전혀 반영하지 않는다
- 30일이라는 단일 홀드아웃 구간의 결과이므로 다른 구간에서는 순위가 바뀔 수 있다

## 8. 리포트 구조 (`REPORT.md`)

1. 분석 주제 및 선정 이유
2. 분석 질문 (5개)
3. 데이터 설명 (출처, 기간, 데이터 수, 컬럼, 라이선스 주의)
4. 데이터 정제 과정 (결측치·이상치 처리 기준과 근거)
5. 분석 결과 및 시각화 (그래프 5개 + 각 그래프별 관찰 서술)
6. 인사이트 (3개 이상) — 각 항목을 아래 형식으로 작성
   - **관찰(Fact)**: 그래프/표에서 확인한 수치와 구간
   - **해석(Why)**: 가능한 원인 가설 1~2개
   - **행동(Action)**: 의사결정 제안 또는 다음 분석 과제
7. 보너스: 베이스라인 예측 결과와 한계
8. 결론 및 한계점
9. AI 사용 로그 (사용 작업 / 사용 이유 / 검증 방법)

### 서술 원칙

**관찰과 해석을 반드시 분리한다.** 데이터에서 직접 읽은 수치는 사실로, 원인 추정은 가설로 표기한다.

**이벤트 연결 가설은 검증 대상으로 표시한다.** AI의 지식 기준일은 2026년 5월이므로, 그 이후 구간의 급등락을 특정 뉴스·사건과 연결한 서술은 사실이 아닐 수 있다. 해당 문장은 가설임을 명확히 하고, 학습자가 직접 확인·수정할 수 있도록 표시한다. 이는 미션의 "AI 도움을 받더라도 최종 판단은 본인이 근거를 들어 설명할 수 있다"는 학습 목표에 대응한다.

## 11. GitHub 업로드 절차

GitHub CLI(`gh`)가 설치되어 있지 않으므로 다음 순서로 진행한다.
